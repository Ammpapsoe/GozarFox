## Gozar 1.11.3 — integrated tunnel diagnostics (draft)

- Integrates bounded Android tunnel DNS/exit diagnostics and packet-drop accounting with the signed updater and transport-reset hardening. Truncated or malformed DNS responses are unknown, and unrelated A records do not count as a successful probe.
- Concurrent identical DNS queries share one in-flight lookup even when the resolver fails; failures are not cached. A closed TCP DNS pipe no longer publishes a late learned answer. Candidate attempt scoping separates DNS flights and cached replies across reconnects and checks stale DNS work before fallback and publication; in-flight network operations can still race a stop. Gated 50-race stresses exercise these cases.
- Android lifecycle hardening tracks and aborts established HTTP/1 and HTTP/2 duplexes on transport reset, stops transport when `FoxLink.stop()` runs, and binds verification, proxy, and TUN worker opens to their attempt. Candidate changes preserve and pause listener ports across same-interface retries, guard replacement services against stale teardown, and register pending direct and relay sockets for cancellation. Loopback 50-race tests cover pending proxy, TLS and H1-response operations; Android physical-device behavior and GitHub Actions on the final commit require verification. Packets already sent, DNS cancellation, root-session overlap and service lifetimes remain limitations; this is not a kill switch.
- Diagnostics observe traffic through the app's tunnel only; they do not prove device-wide DNS, IPv6, WebRTC, split-tunnel or kill-switch leak freedom.
- A bounded DATAGRAM-capsule codec and a desktop HTTP/2 CONNECT-UDP stream prototype pass synthetic loopback tests, including forwarding to a local UDP echo server. They are disabled and not connected to the packet stack; application UDP and production relay compatibility remain unverified.
- A user-authorized real-account CI test accepted an email verification code but encountered HTTP 406 on the following OAuth request; changing the request's compression preference did not resolve that test. No real relay or end-to-end account login was established. See `docs/real-account-validation.md`.
- Synthetic Android app tests reproduced a consumed-code retry, duplicate-verification race, late login publication after logout, and a stale busy-indicator race. The draft retains a verified session for a user-initiated retry, serializes login-operation bodies, revokes late publication on logout, and derives the busy indicator from active work. These tests do not resolve or explain OAuth HTTP 406 and have not been verified with the real account.
- Installation and automatic recovery across platforms, production data migration and real-world connectivity goals remain incomplete. Do not publish as a stable release without separate evidence and review.
