## Gozar 1.13.0 — بازسازی کامل ورود با WebView و WebChannel

**این نسخه Prerelease است، نه Stable.**

## فارسی

### چه چیزی درست شد
- **ورود به حساب فایرفاکس از نو ساخته شد.** روش قبلی (Custom Tab) از نظر ساختاری نمی‌توانست کد ورود را دریافت کند: سرورهای موزیلا کد را فقط به نشانی بازگشت ثبت‌شده در پایگاه خودشان یا به کانال WebChannel داخل صفحه می‌دهند و Custom Tab هیچ‌کدام را ندارد. به‌همین دلیل هر تلاش با پیام «Something went wrong» تمام می‌شد.
- **کلید مشتری (client id) به مقدار عمومی و درست برگشت.** کلید محرمانه‌ی «Mozilla VPN» که در نسخه‌های خراب جایگزین شده بود، گرفتن توکن بدون client_secret را برای همیشه ممنوع می‌کرد (errno 109).
- **خطای 451 دیگر بن‌بست نیست.** یک تلاش مجدد با مسیر دوتاشده انجام می‌شود — همان رفتاری که مشتری رسمی موزیلا دارد — و نه حلقه، نه داخل تونل کنترل.
- **برنامه دیگر با Restart شدن سرویس‌های گوگل نمی‌میرد.** وابستگی startup به فراهم‌کننده‌ی فونت Play services (emoji2) حذف شد؛ ایموجی‌ها با گلیف‌های خود سیستم نمایش داده می‌شوند.
- **به‌روزرسانی توکن تنها با یک قفل سراسری** انجام می‌شود تا تونل و رابط کاربری توکن چرخشی را دوبار مصرف نکنند؛ توکن ردشده توسط موزیلا (errno 108/109/110/115 یا HTTP 400/401) دور ریخته می‌شود و کاربر به صفحه‌ی ورود برمی‌گردد، نه اینکه در حالت خراب بماند.

### ورود با WebView چگونه کار می‌کند
- صفحه‌ی ورود موزیلا داخل یک WebView متعلق به خود برنامه باز می‌شود با سخت‌گیرانه‌ترین تنظیمات: بدون دسترسی فایل، بدون دسترسی محتوای cross-origin، MIXED_CONTENT_NEVER_ALLOW، مرور امن روشن، بدون پنجره‌ی اضافه، بدون مکان‌یابی، بدون ذخیره‌ی رمز و فرم، بدون کوکی شخص ثالث.
- یک اسکریپت relay در لحظه‌ی document-start پیام‌های WebChannel صفحه را به سمت کاتلین می‌برد. اعتبارسنجی فقط در کاتلین است: مبدأ باید دقیقاً `https://accounts.firefox.com` باشد، فقط فریم اصلی، شناسه‌ی کانال `account_updates`، سقف ۶۴ کیلوبایت پیش از تجزیه، و sessionToken باید ۶۴ کاراکتر هگز باشد. پیام ردشده فقط نام بررسیِ شکست‌خورده را حمل می‌کند، نه محتوای پیام را.
- `addJavascriptInterface` در هیچ‌جای برنامه استفاده نمی‌شود.
- توکن‌ها با همان گاوصندوق همیشگی (AndroidKeyStore AES/GCM یعنی SecretBox + FoxStore) رمزنگاری و نگهداری می‌شوند؛ هیچ توکنی در لاگ نوشته نمی‌شود.
- تعویض کلید مشتری به مقدار عمومی `5882386c6d801776` یعنی موزیلا تحویل از طریق WebChannel را برای همین کلید ثبت کرده است — همان مسیری که این نسخه استفاده می‌کند.

### چه چیزی حذف شد
- `MozillaAuthActivity` و layout آن، `FoxOAuth` و تست آن، `FoxApi.oauthCode/profile` و `FoxProfile`، `Fox.completeOAuth`، فیلتر intent روی `https://vpn.mozilla.org/oauth/success`، و وابستگی `androidx.browser`. هیچ کامنت خالی یا کد مرده‌ای به‌جا نمانده است.

### آزمایش‌ها (GitHub Actions)
- ۲۳۲ تست واحد در `core` و ۱۲۴ تست در `app` — همه سبز، از جمله ۳۹ تست تازه برای WebChannel، مدیریت توکن، سربرگ‌ها و اسکریپت مرورگر.
-_job امولاتور (API 34): چهار قاب از صفحه‌ی نخست، صفحه‌ی ورود و WebView ضبط شد؛ **صفحه‌ی واقعی ورود موزیلا داخل WebView برنامه رندر شد** و گزارش توانمندی‌ها تأیید می‌کند `WEB_MESSAGE_LISTENER` و `DOCUMENT_START_SCRIPT` روی تصویر فعال‌اند.

### محدودیت‌ها — هنوز لازم است
- آزمایش ورود با حساب زنده از دیتاسنتر CI کامل نشد (`WEBVIEW_STATE=EMPTY`)؛ لبه‌ی موزیلا از IP دیتاسنتر نشست زنده برنمی‌گرداند. به‌همین دلیل این نسخه Prerelease منتشر می‌شود و کانال Stable پس از آزمایش دستگاه فیزیکی باز می‌شود.
- **آزمایش روی دستگاه فیزیکی و با ISP ایرانی انجام نشده و باید انجام شود.** همه‌ی شواهد بالا از دیتاسنتر گیتهاب در آمریکا است؛ رفتار لبه‌ی موزیلا و چالش‌های مشتری‌نمای آن از IP خانگی ایران می‌تواند متفاوت باشد.
- سهمیه‌ی رایگان ۵۰ گیگابایت تنها تا وقتی معتبر است که موزیلا سرویس FPN را برای حساب شما فعال نگه دارد.
- WebView دستگاه باید به‌روز باشد؛ روی WebView خیلی قدیمی برنامه به‌جای نمایش فرمی که هرگز کامل نمی‌شود، پیام راهنما نشان می‌دهد.

### امضا
- این نسخه با **همان هویت امضای v1.11.5** امضا شده است (نه هویت قدیمی‌تر)؛ بنابراین ارتقا از ۱٫۱۱٫۵ بدون حذف نصب انجام می‌شود.

## English

### What was fixed
- **Firefox account sign-in was rebuilt.** The previous Custom Tab path could not have received an authorization code: Mozilla delivers codes only to a redirect URI registered in their own database or to the page's WebChannel, and a Custom Tab offers neither. Every attempt ended in "Something went wrong. Please close this tab and try again."
- **The client id is the correct public one again.** The confidential Mozilla VPN client id that the broken revisions had switched in forbids token exchange without a client secret (errno 109), permanently.
- **HTTP 451 is no longer a dead end.** One retry with a doubled leading slash - the official client's behaviour - never a loop, never inside the control tunnel.
- **The app no longer dies when Play services restart.** The emoji2 startup dependency on the Play services fonts provider is gone; emoji render with the platform's own glyphs.
- **Token refresh happens under one process-wide lock**, so the tunnel and the UI cannot consume a rotating token twice; a credential Mozilla refuses (errno 108/109/110/115 or HTTP 400/401) is forgotten and the user returns to sign-in instead of being stuck.

### How the WebView login works
- Mozilla's sign-in page opens in a WebView the app owns, with the strictest settings: no file or content access, no cross-origin file reads, MIXED_CONTENT_NEVER_ALLOW, safe browsing on, no extra windows, no geolocation, no saved passwords or form data, no third-party cookies.
- A relay script injected at document-start forwards the page's WebChannel messages to Kotlin. Validation lives only in Kotlin: origin exactly `https://accounts.firefox.com`, main frame only, channel id `account_updates`, a 64 KiB cap enforced before parsing, and a 64-hex sessionToken. A rejected message carries only the name of the failed check, never its content.
- `addJavascriptInterface` is not used anywhere in the app.
- Tokens are stored with the same vault as always (AndroidKeyStore AES/GCM: SecretBox + FoxStore); no token is ever logged.
- The client id is the public `5882386c6d801776`, for which Mozilla registered WebChannel delivery - exactly the path this release uses.

### What was deleted
- `MozillaAuthActivity` and its layout, `FoxOAuth` and its test, `FoxApi.oauthCode/profile` and `FoxProfile`, `Fox.completeOAuth`, the intent filter on `https://vpn.mozilla.org/oauth/success`, and the `androidx.browser` dependency. No comment stubs or dead code left behind.

### Testing (GitHub Actions)
- 232 unit tests in `core` and 124 in `app`, all green, including 39 new tests for the WebChannel, token manager, headers and browser script.
- Emulator job (API 34): four frames captured of the first screen, the login screen and the WebView; **Mozilla's real sign-in page rendered inside the app's WebView**, and the capability report confirms `WEB_MESSAGE_LISTENER` and `DOCUMENT_START_SCRIPT` are live on the image.

### Limitations - still required
- Live-account sign-in from the CI datacenter did not complete (`WEBVIEW_STATE=EMPTY`); Mozilla's edge does not return a live session to a datacenter IP. This release is therefore published as a Prerelease, and the Stable channel opens after physical-device validation.
- **No physical-device or Iranian-ISP test has been performed; both remain required.** All evidence above comes from a GitHub datacenter in the US; Mozilla's edge behaviour and client-challenge responses can differ from a residential Iranian IP.
- The free 50 GB allowance is valid only while Mozilla keeps FPN enabled for your account.
- The device WebView must be current; on a very old WebView the app shows guidance instead of a form that could never complete.

### Signing
- This release is signed with **the same identity as v1.11.5** (not the older one), so upgrading from 1.11.5 needs no uninstall.
