# Gozar 1.17.1

## فارسی

- **رفع کرش «اتصال» (Send feedback):** در بیلد release، بهینه‌ساز R8 نام متد `toLeakAwareBuffer` کتابخانهٔ netty را تغییر می‌داد؛ netty هنگام آماده‌سازی بافر دقیقاً همین نام را با `getDeclaredMethods()` جستجو می‌کند و چون پیدایش نمی‌کرد با `IllegalArgumentException` می‌مُرد — کل ترد تانل با `ExceptionInInitializerError` از کار می‌افتاد و دکمهٔ «اتصال» هر بار کرش می‌کرد. رفع تنها با سه قانون `-keep` دقیق روی همان سه کلاس netty (`ReferenceCountUtil`، `AbstractByteBufAllocator`، `AdvancedLeakAwareByteBuf`) انجام شد.
- **منطق لاگین/ورود هیچ تغییری نکرده است:** مسیرهای ورود (فرم native، WebView Mozilla، رلهٔ Apps Script، چالش 406) نسبت به ۱.۱۷.۰ و ۱.۱۶.۰ دست‌نخورده‌اند؛ کد `-dontwarn` قبلی فقط هشدارها را ساکت می‌کرد و این علت کرش نبود.
- **هنوز prerelease است:** این اصلاح روی خط لولهٔ جدید تانل (hev) اثر مستقیم دارد و به تأیید روی دستگاه فیزیکی نیاز دارد؛ اتوماسیون WebView حساب‌ها ادعایی نمی‌شود. تا تأیید شما، ۱.۱۷.۰ به stable ارتقا نمی‌یابد.
- اگر بعد از نصب این نسخه هم ورود انجام نشد، لاگ `AUTH failure … (http=… errno=… stage=…)` از دستگاه بفرستید تا دقیق ببینیم شبکه/رله چه پاسخی می‌دهد.

## English

- **Fix the Connect crash ("Send feedback"):** in release builds, R8 renamed netty's `toLeakAwareBuffer` method; netty locates it by exact name via `getDeclaredMethods()` when its buffer allocator initialises, so class init died with `IllegalArgumentException` and the tunnel worker thread crashed with `ExceptionInInitializerError` — every Connect attempt took the app down. The fix is three precise `-keep` rules for exactly the classes netty probes this way (`io.netty.util.ReferenceCountUtil`, `io.netty.buffer.AbstractByteBufAllocator`, `io.netty.buffer.AdvancedLeakAwareByteBuf`). The earlier `-dontwarn` rules only silenced warnings and were not a fix.
- **The sign-in / login flow is unchanged:** all sign-in paths (native form, Mozilla WebView, Apps Script relay, the 406 challenge solver) are byte-identical to 1.17.0 and to 1.16.0; nothing about the account logic was touched.
- **Still a prerelease:** the new native tunnel path needs validation on a physical device; WebView account automation is not claimed. v1.17.0 will not be promoted to stable until this is verified.
- If sign-in still fails after this build, send the on-device `AUTH failure … (http=… errno=… stage=…)` log line so the exact network/relay response can be seen.
