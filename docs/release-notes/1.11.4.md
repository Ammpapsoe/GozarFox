## Gozar 1.11.4 — ورود خودکار با Tor تعبیه‌شده / Embedded automatic Tor login

**مهم:** ورود واقعی بدون VPN و اتصال مستقیم موزیلا پس از ورود روی گوشی فیزیکی هنوز تأیید نشده‌اند. تست native روی emulator میزبان GitHub در این انتشار skip شده و اعتبارسنجی دستگاه واقعی به آزمون کاربر موکول شده است. برای ترافیک حساس به این نسخه تکیه نکنید و نتیجهٔ آزمون را طبق `docs/physical-device-tor-validation.md` گزارش کنید.

### تغییرات

- Tor، Snowflake و Meek داخل برنامه تعبیه شده‌اند؛ Orbot یا برنامهٔ جداگانه لازم نیست. ورود به‌صورت خودکار direct Tor، Snowflake و سپس Meek را امتحان می‌کند و در این مرحله فقط `در حال اتصال امن...` نمایش داده می‌شود.
- دسترسی SOCKS به coroutine ورود محدود است. پل loopback داخلی نام میزبان را با SOCKS ATYP=DOMAIN به Tor می‌دهد تا Java آن را محلی resolve نکند. مقصدها و مسیرهای حساب Mozilla، allowlist مستقل و SPKI pinning رله حفظ شده‌اند.
- پس از پایان احراز هویت، Tor، IPtProxy، listenerها و فایل‌های موقت حذف می‌شوند و ارتباط بعدی موزیلا مستقیم است. خطای حساب باعث ارسال دوبارهٔ credential روی transport دیگر نمی‌شود.
- Discovery با امضا و اعتبار زمانی حداکثر ۲۴ ساعته، fail-closed است. کنترل tunnel در scope جداگانه روی 451 به Worker fallback نمی‌رود.
- بسته‌ها فقط برای `arm64-v8a`، `armeabi-v7a` و `x86_64` و به‌صورت ABI split ساخته می‌شوند؛ universal APK و WebTunnel بدون bridge معتبر وجود ندارد.

### اعتبارسنجی و محدودیت‌ها

مسیر انتشار compile، JVM unit test هسته و اندروید، آزمون‌های دسکتاپ، بررسی مرزهای ABI و ساخت امضاشده را اجرا می‌کند. native Android instrumentation روی emulator میزبان نتیجهٔ موفقی تولید نکرد و از workflow این انتشار حذف شده است؛ این حذف به معنی اثبات سازگاری گوشی نیست. موفقیت bootstrap یا پاسخ‌های synthetic به‌عنوان real first-login محسوب نمی‌شود.

رله‌های Worker فعلی ممکن است همچنان با 403/1010 مسدود شوند. عملکرد از شبکهٔ کاربر، موفقیت اولین ورود واقعی، توقف کامل Tor روی همهٔ دستگاه‌ها و نبودن device-wide leak هنوز تأیید نشده است.

---

**Important:** Real first login without VPN and direct Mozilla tunnel establishment after login have not been validated on a physical phone. Hosted native emulator testing is skipped for this release and physical-device validation is deferred to the user. Do not rely on this build for sensitive traffic; report results using `docs/physical-device-tor-validation.md`.

### Changes

- Embeds Tor, Snowflake and Meek with no Orbot or separate application. Login automatically tries direct Tor, Snowflake, then Meek and displays only `در حال اتصال امن...` during transport selection.
- Scopes SOCKS to login, forwards unresolved hostnames through a loopback bridge using SOCKS ATYP=DOMAIN, retains strict destination allowlists and relay SPKI pins, and stops Tor/transport state after authentication. Account failures never resend credentials over another transport.
- Retains signed, fail-closed Discovery and direct post-login Mozilla routing. Control-scoped 451 responses do not trigger Worker fallback.
- Ships only arm64-v8a, armeabi-v7a and x86_64 ABI splits. No universal APK, unvalidated WebTunnel bridge or invented fallback is included.

### Validation and limitations

The release path runs compilation, Android/core JVM tests, desktop tests, ABI boundary checks and signed packaging. Hosted native Android instrumentation did not pass and is excluded from this release workflow; this is not evidence of device compatibility. Synthetic responses and bootstrap are not real-login evidence. Worker relays may still be blocked, and real-network login, physical-device shutdown behavior and device-wide leak freedom remain unvalidated.
