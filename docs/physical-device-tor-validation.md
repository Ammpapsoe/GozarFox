# اعتبارسنجی Tor تعبیه‌شده روی دستگاه واقعی

این چک‌لیست برای Gozar 1.11.4 است. تست native روی emulator میزبان GitHub در این انتشار اجرا نمی‌شود. compile و unit test سبز، به‌تنهایی موفقیت ورود واقعی یا سازگاری همهٔ گوشی‌ها را ثابت نمی‌کند.

## ایمنی و آماده‌سازی

- از یک حساب آزمایشی استفاده کنید، نه حساب اصلی. رمز، کد ایمیل، access token، refresh token و شناسهٔ حساب را در گزارش یا تصویر نفرستید.
- نسخه و ABI را قبل از نصب بررسی کنید:

  ```sh
  adb shell getprop ro.product.cpu.abi
  adb shell dumpsys package com.gozar | grep -E 'versionCode|versionName'
  ```

- برای بیشتر گوشی‌های جدید فایل `Gozar_1.11.4_arm64-v8a.apk` مناسب است. برای `armeabi-v7a` و `x86_64` فقط فایل همان ABI را نصب کنید.
- نصب یا ارتقا:

  ```sh
  adb install -r Gozar_1.11.4_arm64-v8a.apk
  ```

- VPN دیگر، Orbot، always-on VPN و proxy دستی Wi-Fi را خاموش کنید. Gozar نباید برای ورود به Orbot یا برنامهٔ جداگانه نیاز داشته باشد. نوع شبکه و وضعیت Private DNS را فقط در گزارش بنویسید؛ تغییر DNS یا نصب CA آزمایشی لازم نیست.
- برنامه را Force stop کنید و شبکه را یک بار قطع/وصل کنید تا آزمون از حالت سرد شروع شود.

## آزمون اولین ورود بدون VPN

1. در حالی که هیچ VPN دیگری فعال نیست، Gozar را باز کنید.
2. با حساب آزمایشی وارد فرایند اولین ورود شوید؛ برای این آزمون نباید Mozilla pass یا relay secret از قبل در دستگاه وجود داشته باشد.
3. هنگام انتخاب خودکار مسیر، متن قابل مشاهده باید فقط `در حال اتصال امن...` باشد. نام Tor، Snowflake، Meek، آدرس bridge و جزئیات bootstrap نباید نمایش داده شود.
4. برنامه باید بدون انتخاب دستی transport، به ترتیب direct Tor، Snowflake و Meek را امتحان کند. ترتیب واقعی انتخاب از روی UI قابل مشاهده نیست و نباید حدس زده شود.
5. اگر ورود موفق شد، اتصال Mozilla را همان‌جا و بدون روشن‌کردن Orbot برقرار کنید. موفقیت ورود و برقراری tunnel را جداگانه ثبت کنید.
6. اگر خطا رخ داد، فقط زمان، نوع شبکه و متن عمومی خطا را ثبت کنید. رمز، کد یا token را در گزارش نیاورید.

## بررسی توقف Tor و مسیر مستقیم پس از ورود

پس از موفقیت و پایان ورود، Tor و listenerهای transport باید متوقف شوند و tunnel موزیلا مستقیم برقرار شود. روی build غیر debuggable، نبودن سرویس را می‌توان با این فرمان بررسی کرد؛ خروجی خالی به‌تنهایی اثبات network leak نبودن نیست:

```sh
adb shell dumpsys activity services com.gozar | grep -E 'TorService|IPtProxy'
```

- نمونهٔ خروجی services را در صورت تمایل و پس از حذف شناسه‌های حساب نگه دارید.
- بدون Orbot، فهرست سرورها را تازه و tunnel را وصل کنید. این مسیر نباید به Tor SOCKS قبلی وابسته باشد.
- اتصال را قطع و دوباره وصل کنید، برنامه را Force stop و دوباره باز کنید و یک بار بین Wi-Fi و اینترنت سیم‌کارت جابه‌جا شوید.
- آدرس IP عمومی را قبل و بعد از اتصال با یک سرویس بررسی IP مقایسه کنید. این فقط یک بررسی رفتاری است و اثبات کامل نبودن DNS/IP leak نیست.

## گزارش نتیجه

این قالب را بدون اطلاعات حساب تکمیل کنید:

```text
نسخه: 1.11.4 (versionCode 41)
مدل گوشی:
نسخهٔ Android و build سیستم:
ABI:
نوع شبکه و وضعیت Private DNS:
VPN/Orbot دیگر خاموش بود: بله / خیر
اولین ورود واقعی موفق شد: بله / خیر
فقط متن «در حال اتصال امن...» دیده شد: بله / خیر
Tunnel موزیلا پس از ورود برقرار شد: بله / خیر
TorService پس از ورود در dumpsys دیده شد: بله / خیر
قطع/وصل و Force stop/restart:
جابه‌جایی Wi-Fi/سیم‌کارت:
زمان تقریبی تا ورود و تا اتصال:
خطای عمومی، بدون رمز/token/شناسهٔ حساب:
```

اگر logcat لازم است، فقط خطای مربوطه را خصوصی نگه دارید و پیش از ارسال، رمز، ایمیل، token، cookie، آدرس IP شخصی و شناسه‌های حساب را حذف کنید. bootstrap موفق، پاسخ ساختگی یا unit test سبز نباید به‌عنوان موفقیت real first-login گزارش شود.
